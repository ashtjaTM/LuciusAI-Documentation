## Code Editor

The **Code editor** provides access to the **Playwright code generated for the test case**. Each test step is represented in the editor as a corresponding `test.step()` block, with the Playwright implementation generated for that step during the **Generate** process.

### Code Generation State

Before the test case has been generated, the Code editor displays the test-step structure with a **“Code not generated yet.”** message for steps that do not have generated Playwright code. Once the test case is generated, the corresponding Playwright implementation is populated against the relevant test steps. The generated code reflects the browser actions associated with each step.

For example, a step such as **“Go to** **`https://aurellis.fashion/`****”** is represented by its corresponding Playwright implementation, such as a `page.goto()` action.

### Code Editor Controls

The Code editor provides controls for working with the generated test implementation:

- **Run** — Runs the Playwright code from the Code editor and executes the generated test implementation.
- **Reset** — Resets the current execution index back to the **first test step**, allowing execution to start again from the beginning.
- **Console** — Toggles the visibility of the **Console** panel below the code editor.
- **Fullscreen** — Expands the Code editor to provide a larger editing and viewing area.
- **Close** — Closes the expanded Code editor view.

### Step-Level Code

The generated Playwright code is associated with each individual test step, and each step provides controls for working with its corresponding code.

- **Edit Step Code** — Use the **Edit** icon beside a step to modify the Playwright code associated with that specific test step.
- **Run Individual Step** — Use the **Run** icon beside a step to execute that particular test step individually. This allows the user to validate or re-execute a specific step without running the entire test case.
- **Add Step** — The **Add step** option available within the Code editor allows the user to add a new test step directly from the Code editor view. The newly added step can then have its corresponding Playwright implementation generated as part of the test case.

The Code editor therefore provides both **test-case-level code controls** and **step-level controls**, allowing users to add, edit, and individually execute test steps directly within the generated Playwright code.

During execution, the Code editor reflects the execution state of individual steps. The status indicator associated with a step changes as execution progresses, allowing the user to identify which generated code has completed successfully and which step is currently executing or has encountered an error.

## Console

The **Console** is the output panel associated with the Code editor. It can be displayed or hidden using the **Console** control in the Code editor toolbar. During test execution, the panel is used to display the **execution-related console output** generated by the test.

The Console also provides controls to:

- **Show or hide the Console** using the Console toggle in the Code editor toolbar.
- **Download** the available console output.
- **Copy** the console output for use elsewhere.

The Console can therefore be used alongside the generated Playwright code to inspect the output produced during test execution, while the Code editor provides the corresponding implementation being executed.

### Code Editor and Console Together

The Code editor and Console work together during test execution:

1. The test case contains its generated Playwright implementation.
2. The Code editor displays the generated code mapped to the individual test steps.
3. The test can be executed from the available **Run** control.
4. The **Console** can be enabled to view the resulting execution output.
5. The execution index can be reset to the first step when the user needs to restart execution from the beginning.
6. Individual test-step code can be edited where required.

This makes the Code editor the primary area for **reviewing, executing, and modifying the generated Playwright implementation**, while the Console provides the corresponding **execution output**.
